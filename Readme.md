# Random 30 Digits Saver

Chrome-расширение (Manifest V3), которое переименовывает скачиваемые изображения в случайное 30-значное число вместо «загрузка(1).jpg», «img_00234.png» и подобных автоматически сгенерированных имён.

## Что делает

- **Автопереименование при загрузке.** Если браузер скачивает картинку с «плохим» именем (по настраиваемому списку паттернов), расширение подменяет имя на 30 случайных цифр, сгенерированных через `crypto.getRandomValues` (криптографически стойкий источник случайности, а не `Math.random()`).
- **Кнопка Save на картинках.** При наведении на любое изображение крупнее 150×150px в правом верхнем углу появляется кнопка 💾 Save. Клик скачивает картинку и **всегда** переименовывает её в случайное имя — независимо от того, «плохое» исходное имя или нет.
- **Настраиваемые паттерны.** Страница настроек (клик по иконке расширения) позволяет задать список правил, по которым имя считается «плохим»: простые подстроки (`download`) или regex в слэшах (`/^img_\d+/`).
- **Расширение изображения определяется по MIME-типу** (`Content-Type` из ответа сервера), с fallback на расширение в самом имени файла — MIME надёжнее, так как имя может быть неточным (например, при неверно настроенном `Content-Disposition` на сервере).

## Установка (режим разработчика)

1. `chrome://extensions`
2. Включить **Режим разработчика** (переключатель в правом верхнем углу)
3. **Загрузить распакованное расширение** → выбрать папку с файлами проекта
4. Добавить иконки в `icons/icon16.png`, `icons/icon48.png`, `icons/icon128.png` (манифест ссылается на них, но сами файлы не входят в репозиторий)

## Структура файлов

| Файл | Назначение |
|---|---|
| `manifest.json` | Конфигурация MV3: permissions (`downloads`, `storage`), `<all_urls>` для content script и загрузок |
| `background.js` | Service worker: слушает `chrome.downloads.onDeterminingFilename`, решает переименовывать или нет, генерирует случайное имя |
| `content.js` | Внедряется на все страницы: отслеживает наведение на `<img>`, показывает кнопку Save, по клику шлёт сообщение в background |
| `style.css` | Стили кнопки Save |
| `options.html` / `options.js` | Страница настроек паттернов, хранение через `chrome.storage.sync` (синхронизируется между устройствами пользователя) |

## Как работает переименование изнутри

Два независимых пути приводят к переименованию:

1. **Обычная загрузка браузером** (клик правой кнопкой → «Сохранить изображение как», прямая ссылка на файл и т.п.) — проверяется по `hasBadName()` против списка паттернов из настроек. Если имя «хорошее» — не трогается.
2. **Загрузка через кнопку Save** — переименовывается всегда, вне зависимости от исходного имени.

Различение этих двух путей происходит через `downloadId`, а не URL картинки: `chrome.downloads.download()` возвращает `downloadId` синхронно в колбэке, и именно он сверяется в `onDeterminingFilename`. Это важно, потому что один и тот же URL может встречаться на странице несколько раз, а сам `item.url` в некоторых случаях отличается от URL, переданного в `download()` (например, после редиректов) — трекинг по строке URL в такой ситуации давал гонку состояний.

## Известные ограничения

- **`forceRenameIds` живёт только в памяти service worker'а.** MV3-воркер может выгружаться при простое; если это произойдёт в узком окне между кликом на Save и срабатыванием `onDeterminingFilename`, форс-переименование для этой конкретной загрузки не сработает. На практике происходит редко (события загрузок обычно держат воркер активным), но при переносе на более надёжное хранение стоит использовать `chrome.storage.session` вместо `Set`.
- **После перезагрузки расширения** уже открытые вкладки продолжают работать со старым, невалидным контекстом content script до обновления страницы — `chrome.runtime.sendMessage` в этом случае бросает исключение. Кнопка Save обрабатывает это и показывает «⚠️ Reload page» вместо молчания, но сама загрузка в этом случае не запустится, пока страница не будет обновлена вручную.
- **Паттерн `/^[a-f0-9]{8,}/`** в списке по умолчанию шире, чем может показаться: он совпадает с любым именем файла, целиком состоящим из символов `a-f0-9` и длиной 8+, включая случайные осмысленные слова вроде `face123456.jpg`, а не только хэши.

## Права доступа

- `downloads` — для переименования файлов при загрузке
- `storage` — для хранения списка паттернов (`chrome.storage.sync`)
- `<all_urls>` (host permission + content script) — кнопка Save должна работать на любом сайте, где может быть изображение

Из того, что ещё не финализировано в этом раунде:

storage.session для forceRenameIds вместо обычного Set — если когда-нибудь заметишь, что Save иногда «промахивается» без видимой причины (service worker выгрузился из памяти между кликом и срабатыванием onDeterminingFilename), это первое, что стоит проверить и поправить.

Widescope regex /^[a-f0-9]{8,}/ в дефолтных паттернах — он ловит не только хэши, но и обычные слова вроде face123456.jpg. Не баг, но стоит либо сузить, либо описать в help-text на странице настроек.
Shadow DOM для кнопки — если когда-нибудь столкнёшься с сайтом, где агрессивный CSS ломает вид кнопки Save, это будет фикс.

Ничего из этого не горит — расширение рабочее.
